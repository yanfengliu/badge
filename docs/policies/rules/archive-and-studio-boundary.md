# Archive and Studio boundary

One of [Badge's local rules](../local-rules.md), with the reasons and evidence of each.

Badge serves one host document at `/`, where Collection, Timeline, and Discover are the primary sections selected through root-document view state; legacy HTML navigation under `/studio` redirects into the same document. Badge Studio is not a peer destination: it adjusts one badge, so it opens only from that badge's page in Discover and its location carries the badge as `#studio/<recordId>`, which a reload or a shared link reopens; a Studio location naming no badge resolves to Discover. Because that is the only way in, every badge needs one: an uncollected badge offers it on its preparation page and a collected badge on its memory, or some badge in the archive could not be adjusted at all. The host composer is the sole production module allowed to import both presentation surfaces. Archive and Studio retain separate versioned IndexedDB database names, repositories, persistence namespaces, standalone isolation builds, and backup formats; the one document has one content-security-policy surface, and no route-specific service-worker scope is claimed. Composition never authorizes either application surface to import or open the other's private implementation or database.

The archive never exposes art generation, prompt, candidate, provider, or publish controls, and its own screens render every badge read-only; the single `Adjust in Badge Studio` action on a badge's page routes into Studio rather than editing in place. Every Collection, detail, planning, activation, Timeline, or 3D badge resolves to exactly one validated published source image and presentation recipe pinned by its pack reference and content hash — the four starter PNGs and the digest-bound discovery catalogue pack's canonical JPEG studies both satisfy this. Discover grants no authoring capability; its cards only route into the ordinary preparation, activation, and replay flows.

Badge Studio adjusts exactly eight things about one already-created badge: its picture, shape, material, border color, border width, tags, quote, and which collections it belongs to. It creates no badges — new badges are authored into the catalogue through the repository — and it holds no prompt library, candidate generation, art provider, or pack publishing. A quote is chosen from that badge's own reviewed two-quotation bank and admitted through the same trusted-bank path as any other quotation change; Studio never composes quotation text.

The Archive owns the adjustment. It is a nullable overlay on the record, never a mutation of `publishedVisual`, so a later catalogue reseed or visual upgrade refreshes the shipped badge underneath it and clearing the overlay restores the exact catalogue default. Activation folds the effective visual into `publishedVisual` and pins it; afterwards the badge face and quote are sealed with the memory and only tags and collections stay editable. An owner-supplied image is bytes no shipped catalogue can hand back, so it is required for backup, restore, and recovery closure whether or not the badge is collected, while unearned catalogue art stays excluded and reloads from the bundled tier.

The only thing that crosses between the two surfaces is `@badge/studio-adjustment-contract`: the Archive projects one badge — title, criterion, collected flag, current and catalogue image, catalogue recipe, the overlay's own values, tags, opaque collection keys and labels, and the badge's quotation bank — and Studio returns a submission. No note, date, occurrence, activation, visibility, pack digest, provenance, or database reference crosses in either direction. A collection crosses as an opaque key and a label that Studio returns unread; that key names the pack a catalogue set belongs to, which is release metadata rather than anything about the owner. The handoff is a module the host imports on demand rather than a React registration, because the host suspends the Archive surface's effects while Studio is open and an effect-registered handoff would be missing exactly when it is needed.

The host hides the surface it is not showing, and a hidden surface keeps its state while running no effects. Anything a surface's own state points at therefore outlives that surface's effect cleanup: an object URL revoked there is one the preserved state still names, which blanks the badge a dialog is showing. Release such a resource after the render that replaces it, never on teardown.

The host hides the surface it is not showing, and a hidden surface runs no effects. Anything the rest of the document depends on — opening the archive, the Studio handoff, any state another surface reads — therefore lives beside the singleton that owns it rather than inside a surface's effect, and a write made from one surface refreshes what the other will re-read on being shown rather than only announcing it. Verify this on the cold path: a reload or a shared link straight into a route is the entry a person actually uses, and it is not the path a test that navigates there exercises.

Badge Studio keeps one own-image action, and it receives exactly one piece of lifecycle information: whether the badge is already collected, which seals its face and quote. It preserves the uploaded original unchanged in Studio-local storage and hands the Archive only a re-encoded metadata-free derivative. An owner-supplied picture carries the owner's own accessible description; the catalogue's description belongs to art the badge no longer shows, and a placeholder that describes nothing is not a description. Where none is written, the stored text says whose picture it is rather than what it depicts. It never rewrites an activation pin, date, note, quotation, or other personal field.

Archive Discover consumes only the Git-tracked safe projection of deliberately promoted catalogue studies, their bounded eager list thumbnails, and the integrity-bound on-demand canonical source tier (`assets/discovery-sources.manifest.json`, 896-pixel studies at or below `256 KiB` each) that supplies activation textures and repair bytes, with the owner's adjustments laid over that projection so a badge appears on the shelf they moved it to and their own tags are searchable words. Grids always render the bounded thumbnail tier; one selected badge at a time loads its canonical source. It never imports Studio or catalogue-authoring code, opens Studio persistence, exposes authoring prompts or provenance, or discovers private browser-local projects automatically. Future private Studio work crosses only through an explicit privacy-scrubbed handoff or the ordinary validated publish-and-install path.
