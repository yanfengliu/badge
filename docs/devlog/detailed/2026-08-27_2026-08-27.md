# Devlog — 2026-08-27

## The 384-pixel detail tier left the build

**Why now:** D-055 removed the read-only Discover study dialog — the detail tier's only consumer — so every archive build was still shipping `297` files, `8,136,025` bytes, that nothing rendered, and every catalogue change still paid to regenerate and decode-verify them. The canonical `896 × 896` source tier already serves the selected-detail role and the activation texture.

**What left:** the Archive detail glob and its resolvers, the `discovery-details` Vite output tier and its naming test case, the bundle gate's detail manifest validation, decode invocation, tier bucket, and count arithmetic, the `catalogue:details` and `catalogue:refresh-detail-manifest` npm scripts, `write-discovery-detail-manifest.mjs`, `write-discovery-detail-previews.ps1`, `check-discovery-detail-decode.ps1`, `discovery-detail-decode.test.mjs`, `assets/discovery-details.manifest.json`, and all `297` tracked `assets/*/details/*.jpg` files. The class stays gated on both vectors: the unqualified-JPEG bundle check rejects any detail asset reaching `dist`, and the source-tree decode sweep no longer carves out `details/` directories, so a detail file reappearing in Git fails the stray-asset check directly (an independent critic caught that the first version gated only the bundle vector).

**Numbers that moved:** archive build `1198 → 604` files — the `297` detail JPEGs left along with the `297` per-file lazy-import chunks the non-eager glob had been emitting; bundled JPEG tiers `3 → 2`; catalogue media bytes in dist down `8,136,025` (about `7.76 MiB`), leaving `1,258,975` thumbnail bytes plus `34,319,645` canonical-source bytes. Post-change gate line: “Archive bundle boundary passed for 604 files: 297 bounded list thumbnails (1258975 bytes) and 296 on-demand canonical sources (34319645 bytes), with no retired detail previews, draft Studio candidates, decoder WASM, or WebP runtime markers.”

**For the next session on `wip/code-native-catalogue-rerender`:** the critic disproved this entry's first draft, which claimed that branch edits detail files — `git diff e039712 wip/code-native-catalogue-rerender --name-only` matches zero `details/` paths, so the branch merges over this deletion without conflict. Resuming it still must regenerate thumbnails, integrity records, `catalogue:refresh-pack-fixtures`, and `catalogue:refresh-source-manifest`.

**Gate reliability:** two `archive-fixture-fresh-publish` retry tests with real backoff sat near vitest's default `5s` timeout and flaked under full-suite CPU load (the same class as yesterday's prompt-export and restaurant-residual bumps); their timeouts rose to `60s` so a loaded full run stays truthful.
